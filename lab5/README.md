# Лабораторная работа №5: Мейлслоты (Mailslots)

## 1. Теория: Мейлслоты в Windows

**Мейлслот (Mailslot)** — это механизм межпроцессного взаимодействия (IPC) типа «один-ко-многим» (one-to-many), основанный на датаграммах. В отличие от именованных каналов, мейлслоты предоставляют **недостоверную** доставку сообщений (как UDP) и поддерживают **broadcast/мальтикаст** рассылку.

### Ключевые особенности:
- **Односторонняя связь** — сервер только читает (`GENERIC_READ`), клиент только пишет (`GENERIC_WRITE`)
- **Датаграммная модель** — границы сообщений сохраняются
- **Негарантированная доставка** — сообщения могут теряться, дублироваться, приходить не в порядке
- **Broadcast** — клиент может отправить сообщение **всем** серверам в домене (`\\*\\mailslot\\Name`)
- **Работа в сети** — через SMB (порты 139/445), как и Named Pipes
- **Ограничение размера** — до **424 байт** для датаграмм в сети (локально до 65535 байт при `maxMessageSize=0`)

### Основные API функции:
| Функция | Назначение |
|---------|------------|
| `CreateMailslot` | Создание серверного мейлслота |
| `CreateFile` | Открытие мейлслота для записи (клиент) |
| `ReadFile` | Чтение сообщения (сервер) |
| `WriteFile` | Отправка сообщения (клиент) |
| `CloseHandle` | Закрытие дескриптора |
| `GetMailslotInfo` | Получение информации о мейлслете |
| `SetMailslotInfo` | Установка таймаута чтения |

### Схема взаимодействия:
```
Сервер (Reader)                    Клиент (Writer)
-----------                        -------------
CreateMailslot("\\\\.\\mailslot\\Box")
       |                                 |
       v                                 v
ReadFile()  <--------------------  CreateFile("\\\\*\\mailslot\\Box")
       |                                 |
       |                    WriteFile("Message 1")
       |                                 |
       v                                 v
ReadFile()  <--------------------  WriteFile("Message 2")
       |                                 |
       v                                 v
       ...                             ...
       |                                 |
       v                                 v
ReadFile() получает "STOP"      WriteFile("STOP")
       |                                 |
       v                                 v
CloseHandle()                      CloseHandle()
```

## 2. Структура Mailslot-сервера (читатель)

```cpp
// 1. Создание мейлслота
HANDLE hMailslot = CreateMailslotA(
    "\\\\.\\mailslot\\Box",     // имя мейлслота (локально)
    0,                          // максимальный размер сообщения (0 = без ограничения)
    MAILSLOT_WAIT_FOREVER,      // таймаут ожидания (INFINITE)
    NULL                        // атрибуты безопасности
);

// 2. Цикл чтения сообщений
while (true) {
    DWORD bytesRead;
    char buffer[512];
    
    // Блокирующее чтение до появления сообщения
    ReadFile(hMailslot, buffer, sizeof(buffer)-1, &bytesRead, NULL);
    
    if (bytesRead == 0) continue;  // пустое сообщение
    
    buffer[bytesRead] = '\0';
    
    // Проверка сигнала завершения
    if (strcmp(buffer, "STOP") == 0) {
        cout << "Received STOP signal." << endl;
        break;  // или продолжить ожидание следующей сессии
    }
    
    cout << "Received: " << buffer << endl;
}

// 3. Завершение
CloseHandle(hMailslot);
```

**Важно:** Один мейлслот может принимать сообщения от **множества клиентов одновременно**. Сервер не различает отправителей (нет адреса источника в `ReadFile`).

## 3. Структура Mailslot-клиента (писатель)

```cpp
// 1. Открытие мейлслота для записи
// \\*\\mailslot\\Name — broadcast ко всем серверам с таким именем в домене
// \\Server\\mailslot\\Name — конкретный сервер
// \\.\\mailslot\\Name — локальный сервер
HANDLE hMailslot = CreateFileA(
    "\\\\*\\mailslot\\Box",      // broadcast имя
    GENERIC_WRITE,               // только запись
    FILE_SHARE_READ,             // совместное чтение
    NULL,
    OPEN_EXISTING,               // открыть существующий
    FILE_ATTRIBUTE_NORMAL,
    NULL
);

// 2. Отправка сообщений
for (int i = 1; i <= messageTotal; i++) {
    DWORD bytesWritten;
    WriteFile(hMailslot, message, strlen(message)+1, &bytesWritten, NULL);
    cout << "Sent: " << message << endl;
}

// 3. Сигнал завершения
WriteFile(hMailslot, "STOP", 5, &bytesWritten, NULL);

// 4. Завершение
CloseHandle(hMailslot);
```

## 4. Отличие Mailslots от Named Pipes и сокетов

| Характеристика | Mailslots | Named Pipes | TCP Sockets | UDP Sockets |
|---|---|---|---|---|
| **Модель** | 1-ко-многим (broadcast) | 1-к-1 (duplex) | 1-к-1 (stream) | 1-к-1 / 1-ко-многим |
| **Направление** | Одностороннее (Write→Read) | Двустороннее | Двустороннее | Двустороннее |
| **Надёжность** | Нет гарантий (датаграммы) | Гарантированная | Гарантированная | Нет гарантий |
| **Границы сообщений** | Да | Да (message mode) | Нет | Да |
| **Broadcast** | Да (`\\*\\mailslot\\Name`) | Нет | Нет (только multicast) | Да |
| **Макс. размер (сеть)** | 424 байта | 64 KB+ | Неограничен | 65507 байт |
| **Порядок доставки** | Не гарантирован | Гарантирован | Гарантирован | Не гарантирован |
| **Сложность** | Очень простая | Средняя | Средняя | Низкая |

## 5. Когда выбирать Mailslots

| Сценарий | Причина |
|---|---|
| **Простое уведомление/логирование** | Один сервер собирает логи от множества клиентов |
| **Обнаружение сервисов (Service Discovery)** | Клиент ищет сервер через broadcast |
| **Рассылка событий** | Один отправитель — много получателей |
| **Легковесный IPC без состояния** | Не нужно управлять соединениями |
| **Совместимость с legacy Windows** | Нативный Win32 API |

**Не выбирать, если:** нужна гарантированная доставка, порядок сообщений, двусторонний обмен, большие сообщения (>424 байт в сети), кроссплатформенность.

---

## 6. Важные ограничения Mailslots

1. **Размер сообщения в сети** — максимум **424 байта** для датаграмм через SMB. Локально (на одной машине) можно передавать до 65535 байт при `maxMessageSize=0`.

2. **Нет подтверждения доставки** — `WriteFile` возвращает успех, если сообщение поместилось в локальную очередь, но **не гарантирует** получение сервером.

3. **Нет идентификации отправителя** — сервер не узнает IP/имя клиента.

4. **Буферизация** — входящие сообщения ставятся в очередь. Если сервер не успевает читать — новые сообщения могут отбрасываться (зависит от реализации).

5. **Только SMB** — работает поверх протокола SMB (порты 139, 445), требует доступ к сети/домену.

---

## 7. Безопасность Mailslots

- **ACL** — через `SECURITY_ATTRIBUTES` в `CreateMailslot`
- **Именование** — `\\.\mailslot\Name` (локально), `\\Server\mailslot\Name` (удалённо), `\\*\mailslot\Name` (broadcast)
- **Ограничение доступа** — только локальные пользователи / доменные учётные записи

## 8. Демонстрация работы (из кода лабы)

### Сервер (ServerMS.cpp):
- Создаёт мейлслот `\\.\mailslot\Box` с `MAILSLOT_WAIT_FOREVER`
- Блокирующее чтение через `ReadFile` в бесконечном цикле
- Выводит каждое полученное сообщение
- При получении `"STOP"` выводит время обмена и продолжает ждать новую сессию

### Клиент (ClientMS.cpp):
- Подключается к `\\*\mailslot\Box` (broadcast) через `CreateFile`
- Отправляет заданное число сообщений (`Hello from ClientMS`)
- Измеряет время отправки всех сообщений
- Отправляет `"STOP"` как сигнал завершения сессии

### Запуск:
```cmd
# Терминал 1 — сервер (должен запуститься ПЕРВЫМ)
ServerMS.exe

# Терминал 2 — клиент (10 сообщений)
ClientMS.exe \\\\*\\mailslot\\Box 10
# Аргументы: ClientMS.exe [mailslot_name] [message_count_ignored]
# Обратите внимание: в cmd нужно экранировать слеши \\\\*\\mailslot\\Box
```

## 9. Типичные ошибки и их коды

| Код ошибки | Значение | Решение |
|---|---|---|
| `ERROR_FILE_NOT_FOUND` (2) | Мейлслот не существует | Запустить сервер первым |
| `ERROR_INVALID_NAME` (123) | Неверное имя мейлслота | Проверить формат: `\\Server\mailslot\Name` |
| `ERROR_ACCESS_DENIED` (5) | Нет прав доступа | Проверить ACL / запуск от админа |
| `ERROR_PIPE_BUSY` (231) | Все экземпляры заняты | Для мейлслотов не применимо (один экземпляр) |
| `ERROR_NO_DATA` (232) | Нет данных / канал закрыт | Нормально при завершении |
