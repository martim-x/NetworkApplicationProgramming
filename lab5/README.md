Источник задания: практикум, раздел 7.6 «Использование символических имен компьютеров», задания 1–2. Теория: глава 3, раздел 3.16; глава 2, разделы 2.8.1, 2.8.3.

## 1. Состав работы

| Задание практикума | Файл | Что реализовано |
|---|---|---|
| 1 | `ClientS/ClientS.cpp` | `GetServerByName` — поиск сервера по символическому имени компьютера (`gethostbyname`) и позывному |
| 2 | `ServerB/ServerB.cpp` | сервер печатает своё символическое имя (`gethostname`) и имена клиентов (`gethostbyaddr`) |

Сервер — доработанный `ServerB` из ЛР4 (широковещание), поэтому клиент ЛР4 тоже может работать с этим сервером.

## 2. Теория: как имя превращается в адрес

Символическое имя (например, `WIN11-DESKTOP-T` или `localhost`) — это удобная для человека строка; сокетам нужен 32-битный IPv4-адрес. Преобразование выполняют службы разрешения имён:

| Служба | Что делает | Где используется |
|---|---|---|
| DNS | прямое разрешение «имя → адрес», обратное «адрес → имя» (PTR) | глобальные и локальные сети |
| NetBIOS over TCP/IP | разрешение имён NetBIOS (до 15 символов) в пределах сегмента | старые локальные сети Windows |
| файл `hosts` (`%SystemRoot%\System32\drivers\etc\hosts`) | статические записи без обращения к серверу | локальные псевдонимы вроде `localhost` |
| `gethostname` | сообщает имя текущего компьютера без сети | инициализация сервера |

Ключевые функции Winsock2 (раздел 3.16):

- `gethostbyname(name)` → `struct hostent*`, где `h_name` — каноническое имя, `h_addr_list[0]` — первый IPv4-адрес (в сетевом порядке байт), `h_length` — длина адреса;
- `gethostbyaddr(addr, len, AF_INET)` → `hostent*` для обратного разрешения;
- `gethostname(buf, size)` → имя локального компьютера;
- при неудаче функции возвращают `NULL`, причина — в `WSAGetLastError()` (`WSAHOST_NOT_FOUND`, `WSATRY_AGAIN`, `WSANO_RECOVERY`, `WSANO_DATA`).

Практический смысл для распределённого приложения: вместо жёстко прописанного IP клиент получает имя компьютера из конфигурации и сам находит адрес сервера. Это устойчивее, чем адрес: DHCP может выдать другой IP, а имя останется.

## 3. Протокол поиска по имени

```
Клиент                                  Сервер
gethostbyname("имя") → IP
socket(SOCK_DGRAM)
setsockopt(SO_RCVTIMEO)
sendto("Hello", IP:порт) ------------->  recvfrom → "Hello"?
                                         gethostbyaddr(IP клиента)
recvfrom <------- ответ "Hello" --------  sendto("Hello", адрес клиента)
strcmp(отклик, позывной) → сервер найден
```

Отличие от ЛР4: запрос адресуется конкретному компьютеру (unicast по разрешённому имени), а не всем узлам сегмента. Поэтому здесь не нужен `SO_BROADCAST`, зато нужна работающая служба разрешения имён.

## 4. Разбор по заданиям

**Задание 1.** `GetServerByName(name, call, from, flen)`:
1. создаёт UDP-сокет и ставит `SO_RCVTIMEO` (3000 мс);
2. разрешает `name` через `gethostbyname`; при неудаче печатает причину и возвращает `false`;
3. копирует в `SOCKADDR_IN` номер порта, заранее заполненный вызывающей стороной (по условию `sin_port` должен быть заполнен до вызова), и подставляет разрешённый адрес из `h_addr_list[0]`;
4. отправляет позывной `sendto`, ждёт отклик `recvfrom`;
5. отклик совпал с позывным — `true`, параметры откликнувшегося сервера остаются в `from`; таймаут или чужой отклик — `false`; прочие ошибки — `throw`.

**Задание 2.** Сервер при старте вызывает `gethostname` и печатает своё имя, а для каждого запроса — `gethostbyaddr` по адресу клиента и печатает полученное имя рядом с `IP:порт`.

## 5. Результаты локальной проверки (Windows 11, MSVC 14.51, одна машина)

| Проверка | Ожидание | Факт |
|---|---|---|
| `ClientS WIN11-DESKTOP-T Hello 9103` | имя разрешается, сервер найден | `Имя "WIN11-DESKTOP-T" разрешено в адрес 192.168.31.80`, `Сервер найден: 192.168.31.80:55507` |
| `ClientS localhost Hello 9103` | разрешается в 127.0.0.1, сервер найден | `Сервер найден: 127.0.0.1:55509` |
| `ClientS no-such-host-xyz ...` | отказ разрешения имени | `WSAHOST_NOT_FOUND: Хост не найден`, сервер не найден |
| `ClientS WIN11-DESKTOP-T Other 9103` | имя разрешено, но позывной чужой | `Сервер с позывным "Other" не найден`, сервер: `отклонён чужой запрос` |
| имя сервера (`gethostname`) | печатается | `ServerB: символическое имя компьютера: Win11-Desktop-Tim` |
| обратное разрешение адреса клиента | печатается имя | `Запрос от клиента 192.168.31.80:55506 (имя: host.docker.internal)`, `127.0.0.1 (имя: kubernetes.docker.internal)` |

Две вещи, которые видны только на реальном прогоне и полезны на защите:

- `gethostname` вернул `Win11-Desktop-Tim`, а переменная `COMPUTERNAME` — `WIN11-DESKTOP-T`: имя NetBIOS и имя узла могут различаться (это же сравнение требуется в ЛР1, задание 5);
- обратное разрешение на этой машине уходит в записи `hosts` от Docker (`host.docker.internal`, `kubernetes.docker.internal`), поэтому «имя клиента» не совпадает с именем компьютера. Функция `gethostbyaddr` сообщает то, что вернула служба разрешения имён, а не истину.

**Нестабильность разрешения имени (найдено при повторном прогоне).** Иногда `gethostbyname("WIN11-DESKTOP-T")` возвращает `192.168.56.1` — адрес host-only адаптера VirtualBox, а не `192.168.31.80`. По этому адресу unicast-датаграмма до локального стека не доходит, и клиент сообщает «сервер не найден», хотя сервер запущен и слушает `INADDR_ANY`. После повторного разрешения имя снова указывает на `192.168.31.80`, и поиск работает. Что сделано в коде: `GetServerByName` перебирает **все** адреса из `h_addr_list`, а `WSAETIMEDOUT`/`WSAECONNRESET` (ICMP «порт недоступен») на одном адресе считаются поводом попробовать следующий, таймаут на адрес снижен до 1 с. Если имя разрешается ровно в один «мёртвый» адрес, перебор не спасает — тогда проверять по `127.0.0.1` или по реальному адресу адаптера. Это ограничение среды (VirtualBox), а не логики приложения.

## 7. Сравнение трёх способов найти сервер

| Способ | Лаба | Что нужно знать клиенту | Работает через маршрутизатор | Когда применим |
|---|---|---|---|---|
| Адрес + порт в конфигурации | lab2, lab3 | IP и порт | да | адрес сервера стабилен |
| Широковещательный позывной | lab4 | только порт и позывной | нет (только сегмент) | серверов несколько, адрес неизвестен |

## 8. Вопросы для самопроверки

1. **Что возвращает `gethostbyname` и где в структуре адрес?** Указатель на `hostent`; IPv4-адрес лежит в `h_addr_list[0]` (массив указателей, длина элемента — `h_length`), каноническое имя — в `h_name`.
2. **Почему адрес копируется через `memcpy`, а не присваивается?** `h_addr_list[0]` — указатель на байты в сетевом порядке; присваивать нужно именно байты в `sin_addr`, а не указатель.
3. **Кто заполняет `sin_port` при вызове `GetServerByName`?** Вызывающая сторона: по условию перед вызовом поле `sin_port` уже должно содержать номер порта сервера, функция его не меняет.
4. **Чем `gethostbyaddr` отличается от `gethostbyname`?** Обратное разрешение (адрес → имя); на практике результат зависит от PTR-записей и файла `hosts`, поэтому имя может не совпадать с реальным именем компьютера.
5. **Что будет, если служба разрешения имён недоступна?** `gethostbyname` вернёт `NULL`, код `WSATRY_AGAIN` (временный сбой) или `WSANO_RECOVERY`; клиент должен корректно сообщить об ошибке, а не «зависнуть».
6. **Почему `localhost` работает без DNS?** Он разрешается статической записью в файле `hosts` (`127.0.0.1 localhost`), сетевой запрос не нужен.
7. **Зачем в распределённом приложении символические имена, если есть IP?** Адрес может измениться (DHCP, смена подсети), имя остаётся; клиент получает имя из конфигурации и находит сервер сам.
8. **Почему в этой лабе не нужен `SO_BROADCAST`?** Запрос адресуется одному компьютеру (unicast), широковещательная рассылка не применяется.
