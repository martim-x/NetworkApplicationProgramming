# ЛР8–10: цели и критерии

**Цель:** довести лабораторные 8, 9 и 10 до корректной демонстрации по требованиям защиты, исправить найденные дефекты, обеспечить повторяемую проверку сборкой и автотестами.

## Задачи

1. **ЛР8 — сервер:** исправить разбор TCP-запросов и сохранение данных, покрыть timeout всего подключения, устранить гонки таймера, корректно выполнять `wait`/`shutdown`/`exit`, ждать обслуживания до выгрузки DLL и исправить статистику.
2. **ЛР9 — клиенты:** добавить альтернативный поиск сервера по DNS-имени, надёжно читать/писать TCP-поток, возвращать код ошибки при потере обмена и проверять параметры запуска.
3. **ЛР10 — консоль:** исправить подтверждение и обработку команд, возвращать статистику, отображать серверные события в RConsole и журнале, ограничить зависания pipe.
4. **Проверки:** добавить регрессии для обнаруженных дефектов, интеграционные тесты взаимодействия сервер/клиент/консоль и подключить их к Windows CI.
5. **Завершение:** выполнить полный build и тесты на Windows, разобрать результаты, провести отдельное code review. Работу оставить в ветке `fix/lab8-10-stability`; интеграцию с `main` согласовать отдельно.

## Ограничения

- Уведомления по TCP после закрытия клиентского соединения невозможны. События отключения будут доступны в журнале сервера и через RConsole, согласно выбранному пользователем варианту.
- Реальный прогон с 4–5 клиентами на двух компьютерах требует второй машины; если её нет в окружении, такой критерий останется явно непроверенным.
- Пользователь попросил показать список задач и сообщить результат после выполнения. До завершения не утверждать, что исправления или тесты успешны.
