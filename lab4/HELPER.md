# ЛР4 — команды сборки и запуска (широковещательные адреса)

Все команды — из корня репозитория, в консоли с окружением MSVC (`vcvars64.bat`).

## 1. Сборка

```cmd
cd /d "%USERPROFILE%\Documents\Visual Studio Code\NetworkApplicationProgramming"
if not exist lab4\build mkdir lab4\build
cl /nologo /EHsc /utf-8 /W3 lab4\ServerB\ServerB.cpp /Fe:lab4\build\ServerB.exe
cl /nologo /EHsc /utf-8 /W3 lab4\ClientB\ClientB.cpp /Fe:lab4\build\ClientB.exe
```

| Ключ | Что делает |
|---|---|
| `/EHsc` | стандартная обработка исключений C++ — нужна для `throw string` в обработчиках ошибок |
| `/utf-8` | исходник в UTF-8; без флага MSVC читает его как cp1251 и русский текст в строках ломается |
| `/W3` | уровень предупреждений (на этом коде предупреждений нет) |
| `/Fe:` | имя выходного exe |

Дополнительно линкуется `iphlpapi.lib` (автоопределение широковещательного адреса через `GetAdaptersInfo`) — подключена в исходнике через `#pragma comment`.

## 2. Сервер и клиент на одной машине

Окно 1:

```cmd
cd /d "%USERPROFILE%\Documents\Visual Studio Code\NetworkApplicationProgramming\lab4\build"
ServerB.exe Hello 9101
```

Окно 2:

```cmd
cd /d "%USERPROFILE%\Documents\Visual Studio Code\NetworkApplicationProgramming\lab4\build"
ClientB.exe Hello 9101
```

Ожидаемый вывод клиента (адреса — с машины прогона 2026-10-27; на другой машине будут свои):

```
ClientB: широковещательный поиск сервера "Hello" на порту 9101 (адрес 172.20.10.15)
Получен отклик: "Hello"
Сервер найден: 172.20.10.4:64182
```

Порт в последней строке — **не 9101**: `PutAnswerToClient` создаёт новый сокет без `bind`, поэтому ответ приходит с эфемерного порта, который назначила ОС. Клиент сверяет только позывной, поэтому это нормально.

## 2a. Демонстрация без аргументов (самый короткий путь)

Аргументы у обеих программ необязательные: по умолчанию позывной `Hello`, порт `2000`, широковещательный адрес определяется сам. Ничего вводить руками не нужно — достаточно запустить два exe.

Окно 1:

```cmd
ServerB.exe
```

Окно 2:

```cmd
ClientB.exe
```

Фактический вывод (машина прогона 2026-10-27):

```
ClientB: широковещательный поиск сервера "Hello" на порту 2000 (адрес 172.20.10.15)
Получен отклик: "Hello"
Сервер найден: 172.20.10.4:61315
```

```
ServerB: позывной "Hello", UDP-порт 2000
В сети других серверов с этим позывным не найдено
ServerB: ожидание запросов клиентов...
Запрос от клиента 172.20.10.4:61314
Клиенту отправлен позывной "Hello"
```

**Когда без аргументов не сработает.** Автоадрес берётся из первого адаптера, который вернул `GetAdaptersInfo`. Если первым в списке идёт виртуальный адаптер (VirtualBox host-only `192.168.56.1`, Hyper-V, VPN), клиент отправит запрос в пустую подсеть и напечатает `Сервер с позывным "Hello" не найден` — проверено: `ClientB.exe Hello 2000 192.168.56.255` при работающем сервере даёт именно это. Лечение — задать адрес явно (третий аргумент), взяв его из `ipconfig`:

```cmd
ipconfig
ClientB.exe Hello 2000 172.20.10.15
```

Адрес в скобках, который клиент печатает первым делом, — и есть автоопределённый; если он не из вашей подсети, сразу запускайте с явным третьим аргументом.

## 3. Явное задание широковещательного адреса

```cmd
ClientB.exe Hello 9101 255.255.255.255
ClientB.exe Hello 9101 127.255.255.255
ClientB.exe Hello 9101 172.20.10.15
```

Третий адрес — направленное широковещание своей подсети. Его нужно брать из `ipconfig` на конкретной машине: `IP & маска | ~маска`. При автоопределении программа считает его сама и печатает в скобках.

## 4. Проверка отказов

```cmd
ClientB.exe Other 9101
ClientB.exe Hello 9102
```

Ожидаемо: `Сервер с позывным "..." не найден`.

## 5. Два сервера с одним позывным (задание 6)

Окно 1:

```cmd
ServerB.exe Hello 9101
```

Окно 2 (через пару секунд):

```cmd
ServerB.exe Hello 9101
```

Второй сервер при старте печатает:

```
ВНИМАНИЕ: в сети обнаружены серверы с позывным "Hello": 1 (запрос отправлен до привязки своего сокета)
```

## 6. Другой порт — другой сервер

```cmd
ServerB.exe Hello 9102
ClientB.exe Hello 9102
```

Порт — единственный «адрес» сервера, который клиент знает заранее; позывной уточняет, тот ли это сервер.

## 7. Разбор ошибок

| Сообщение | Причина | Лечение |
|---|---|---|
| `Ошибка: sendto: WSAEACCES` | не выставлен `SO_BROADCAST` | опция уже стоит в коде; если убрать — ошибка вернётся |
| `Сервер ... не найден` сразу после старта сервера | сервер ещё не привязал сокет (опрос сети в `CountServers`) | подождать ~1 с и повторить запрос |
| `Ошибка: bind: WSAEADDRINUSE` | порт занят сокетом, который привязался **без** `SO_REUSEADDR` | взять другой порт (`9102`, `9103`, …); два `ServerB` на одном порту — не ошибка, `SO_REUSEADDR` в коде это разрешает (задание 6) |
| сервер печатает `отклонён чужой запрос` | клиент отправил другой позывной | это ожидаемое поведение задания 1 |
| `Ошибка: socket: WSANOTINITIALISED` | не вызван `WSAStartup` | в коде вызывается в `main` до создания сокетов |
