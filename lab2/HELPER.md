## 2. Уровни модели OSI/ISO и их назначение

Семь уровней (стандарт ISO 7498). Задача каждого уровня — предоставить услуги
вышестоящему уровню, скрыв детали реализации:

1. **Физический** — свойства среды передачи данных (кабель, оптоволокно),
   способы её соединения с сетевыми адаптерами: характеристики кабелей,
   разъёмы, способы обработки сигнала.
2. **Канальный** — два подуровня: управление доступом к среде (MAC) — методы
   совместного использования адаптерами среды передачи; управление логическим
   каналом (LLC) — понятие канала между адаптерами, обнаружение и исправление
   ошибок. Готовит кадр для сетевого уровня.
3. **Сетевой** — методы адресации и маршрутизации; единый метод адресации,
   не зависящий от способа передачи; способы соединения сетей. Результат — пакет.
4. **Транспортный** — подготовка и доставка пакетов между конечными точками
   без ошибок и в правильной последовательности; из пакетов формирует данные
   для сеансового уровня.
5. **Сеансовый** — способы установки и разрыва соединений (сеансов) двух
   приложений. Это точка взаимодействия программ и компьютерной сети.
6. **Представительский** — формат данных приложений: шифрование, сжатие,
   преобразование наборов символов.
7. **Прикладной** — способы взаимодействия пользователей с системой (интерфейс).

Примеры протоколов на каждом уровне:

| Уровень | Примеры протоколов |
|---|---|
| Физический | RS-232, RS-485, USB, Bluetooth (радиоинтерфейс), 1000BASE-T (Ethernet PHY) |
| Канальный | Ethernet (IEEE 802.3), Wi-Fi (IEEE 802.11), PPP, HDLC, ARP* |
| Сетевой | IP (IPv4/IPv6), ICMP, IGMP, IPsec |
| Транспортный | TCP, UDP, SCTP |
| Сеансовый | NetBIOS, RPC, PPTP, L2TP, SOCKS |
| Представительский | TLS/SSL, MIME, ASCII/Unicode (кодировки), XDR, JPEG (для графики) |
| Прикладной | HTTP/HTTPS, FTP, SMTP, POP3, IMAP, DNS, Telnet, SSH, SNMP |

\* ARP формально работает поверх канального уровня, но обычно относится
к стеку TCP/IP между канальным и сетевым.

## 3. Понятие сетевой протокол

Наборы правил и соглашений, описывающих процедуры взаимодействия каждого
уровня модели с соседними уровнями, называются **протоколами**. (Протокол
определяет формат и порядок обмена сообщениями между взаимодействующими
уровнями/системами.)

## 4. Граница между аппаратным и программным обеспечением в OSI/ISO

Граница условно проходит **по канальному уровню**, точнее — между его
подуровнями: часть процедур канального уровня (обычно подуровень управления
доступом к среде, MAC) обеспечивается **аппаратно** — сетевым адаптером, а
другая часть (обычно подуровень управления логическим каналом, LLC) реализована
**в виде драйвера** в составе операционной системы. Протоколы транспортного,
сетевого уровней и выше обеспечиваются службами ОС; сеансовый,
представительский и прикладной — самим приложением.

## 5. Понятие CSMA/CD

CSMA/CD (Carrier Sense Multiple Access with Collision Detection) —
**множественный доступ с контролем несущей и обнаружением конфликтов
(коллизий)**. Метод доступа к среде передачи данных: перед передачей узел
прослушивает среду (контроль несущей), передаёт, если среда свободна, и
обнаруживает коллизию, если одновременно передают два узла; при коллизии
передача прекращается и повторяется после случайной паузы. Применяется в
Ethernet (регулируется семейством стандартов IEEE 802).

## 6. ПО, реализующее подуровень LLC канального уровня

Подуровень LLC реализуется в виде **драйвера** сетевого адаптера,
инсталлированного в состав операционной системы (в Windows — NDIS-драйвер;
см. вопрос 7).

## 7. Что определяет спецификация NDIS

NDIS (Network Driver Interface Specification) — спецификация интерфейса
сетевых драйверов, определяющая **стандартный интерфейс между драйверами
сетевых адаптеров (MAC-уровень) и протоколами стека TCP/IP**, реализуемыми
операционной системой. Благодаря NDIS любой транспортный протокол может
работать с любой сетевой картой: драйвер карты не зависит от протокола,
протокол не зависит от карты.

## 8. Свойства ненадёжных протоколов. Примеры

**Ненадёжный протокол** не гарантирует доставку данных получателю:
- нет гарантии, что отправленный блок данных дойдёт до адресата — сбой на
  любом промежуточном узле может привести к его уничтожению;
- не ведётся учёт очерёдности доставки: каждый блок обрабатывается
  независимо, порядок прихода может нарушаться;
- надёжность и упорядочивание возлагаются на протоколы верхних уровней.

Свойства UDP как типичного ненадёжного протокола: пакеты не упорядочиваются
и не подтверждаются; нет гарантий доставки (повторная передача — забота
прикладного процесса); нет обработки соединений (каждый пакет — независимая
единица); контрольная сумма может вычисляться, но её проверка — на прикладном
процессе; нет буферизации и фрагментации сообщений.

**Примеры:** ненадёжные — IP, UDP, ICMP; надёжный — TCP (защита от повреждения,
потери, дублирования и нарушения очерёдности: нумерация октетов, контрольные
суммы, подтверждения, повторные передачи).

## 9. Уровни модели TCP/IP, назначение, примеры протоколов

Модель **четырёхуровневая** (проще OSI: нет выделенных физического, канального
и представительского уровней):

1. **Уровень доступа к сети** — создание локальных сетей (LAN) и соединение с
   глобальными (WAN). Соответствует физическому + канальному уровням OSI.
   Протоколы: **Ethernet, IEEE 802.2 (LLC), IEEE 802.3 (MAC), SLIP, PPP**.
   Характеристика — MTU (Maximum Transmission Unit).
2. **Межсетевой уровень** — адресация и маршрутизация в составной IP-сети
   (соответствует сетевому уровню OSI). Протоколы: **IP, ICMP, ARP, RARP**,
   а также RIP, OSPF, BGP.
3. **Транспортный уровень** — сквозная доставка данных произвольного размера
   между прикладными процессами. Протоколы: **TCP** (надёжный, с
   установлением соединения, потоковый) и **UDP** (ненадёжный, без
   соединения, ориентированный на сообщения).
4. **Прикладной уровень** — службы TCP/IP и прикладные системы пользователей.
   Соответствует сеансовому + представительскому + прикладному уровням OSI.
   Протоколы/службы: **DNS, DHCP, NBT, Telnet, FTP, SMTP, POP3, IMAP4, HTTP (WWW)**.

## 10. Хост, адрес хоста, имя хоста

- **Хост** (host) — любое устройство, имеющее IP-адрес (в терминологии
  протокола IP): компьютер, маршрутизатор и т.п.
- **Адрес хоста** — IP-адрес: 32-битное (IPv4) число, старшие биты — адрес
  сети, младшие — адрес хоста в этой сети; записывается четырьмя десятичными
  октетами через точку (например 192.168.31.80).
- **Имя хоста** — символическое имя, по которому обращаются к хосту вместо
  числового адреса (DNS-имя вида `microsoft.com`, в Windows также NBT-имя
  компьютера). Посмотреть имя своего хоста — утилита `hostname`; разрешение
  имён в IP-адреса выполняет служба DNS (функции gethostbyname/gethostbyaddr).

## 11. Организация, поддерживающая протоколы Internet. Документы

Шесть групп стандартизации координируют TCP/IP: ISOC, IAB, **IETF**, IRTF,
ISTF, ICANN. Наиболее важная — **IETF** (Internet Engineering Task Force) —
именно она поддерживает документы **RFC (Request for Comments)**, в которых
описаны все правила и форматы протоколов и служб TCP/IP. Всем RFC присвоены
номера; при одноимённых документах текущей считается версия с большим номером.

## 12. MAC-адрес. Структура Ethernet MAC-адреса

MAC-адрес — адрес канального уровня, «зашитый» при изготовлении в память
сетевой платы. В Ethernet — **48-битный** (стандарт IEEE EUI-64-кодировки):
- старшие **24 бита** — код производителя платы (по кодировке ICANN) и партия
  изделия;
- младшие **24 бита** — определяются производителем так, чтобы каждый номер
  был уникален в пределах всей его продукции.

Используется для адресации на канальном уровне; соответствие IP ↔ MAC
устанавливает протокол ARP (ARP-таблица, команда `arp -a`).

## 13. Как посмотреть MAC-адрес сетевой карты

`ipconfig /all` — в полном отчёте о конфигурации TCP/IP для каждого адаптера
указан его физический адрес (Physical Address). Также ARP-таблица: `arp -a`.

## 14. Основное назначение межсетевого уровня

Методы **адресации и маршрутизации** компьютеров в сети: единый, не зависящий
от способа передачи метод адресации (IP-адреса), способы соединения
(объединения) компьютерных сетей в составную IP-сеть через шлюзы, определение
адреса следующего узла в пути следования дейтаграммы (маршрутизация по таблице
маршрутов). Главный протокол уровня — IP, доставляющий дейтаграммы.

## 15. Структура IP-адреса

32-битная последовательность: **старшие (левые) биты — адрес сети, младшие
(правые) — адрес хоста** в этой сети. Для записи используются четыре
десятичных числа через точку, каждое — десятичное представление 8 битов
(октета). Сколько бит отводится сети, а сколько хосту, зависит от модели
адресации (классовая / бесклассовая CIDR). IP-адрес не зависит от физического
устройства подключения (модем, сетевая карта обрабатываются одинаково).

## 16. Типы IP-адресации. Классы адресов Internet

Две модели адресации:
- **Классовая** — все адреса делятся на 5 классов по старшим битам:

| Класс | Диапазон адресов | Частные адреса |
|---|---|---|
| A | 0.0.0.0 – 127.255.255.255 | 10.0.0.0 – 10.255.255.255 |
| B | 128.0.0.0 – 191.255.255.255 | 172.16.0.0 – 172.31.255.255 |
| C | 192.0.0.0 – 223.255.255.255 | 192.168.0.0 – 192.168.255.255 |
| D | 224.0.0.0 – 239.255.255.255 | — (групповые адреса) |
| E | 240.0.0.0 – 247.255.255.255 | — (экспериментальные) |

- **Бесклассовая (CIDR, Classless Inter-Domain Routing)** — граница
  сетевой/хостовой части назначается произвольно; каждому IP-адресу
  прилагается 32-битная маска подсети.

Адреса 127.n.n.n зарезервированы для возвратного тестирования (loopback).

## 17. Публичный и частный IP-адрес

- **Публичный** — уникальный в Internet адрес, маршрутизируемый в глобальной
  сети.
- **Частный** — адрес из зарезервированного для каждого класса диапазона
  (RFC 1918: 10.x.x.x, 172.16–31.x.x, 192.168.x.x). Предназначен для
  неконтролируемого использования внутри организаций: уникальность в Internet
  **не гарантируется**, маршрутизация таких адресов в Internet **невозможна**
  (выход в Internet — через NAT/шлюз).

## 18. Как посмотреть IP-адрес компьютера

`ipconfig` — короткий отчёт о конфигурации TCP/IP; `ipconfig /all` — полный
отчёт (все сетевые параметры, включая MAC-адрес). Особенно полезна на
компьютерах с DHCP.

## 19. Как протестировать IP-соединение в локальной сети

Утилитой **ping** — она использует протокол ICMP: в адрес хоста посылаются
специальные ICMP-пакеты (эхо-запросы), которые по протоколу должны быть
возвращены отправителю (эхо-ответы). `ping hostname`, где hostname — DNS/NetBIOS
имя или IP-адрес. Если ответы приходят — соединение работает.

## 20. Как получить перечень сетевых узлов между двумя хостами

Утилитой **tracert** — как и ping, использует ICMP, определяет маршрут до
пункта назначения: на консоль выводятся **все промежуточные узлы** маршрута
от исходного хоста до пункта назначения и время их прохождения.
`tracert hostname`.

## 21. Параметры настройки TCP/IP

При настройке протокола TCP/IP (окно «Свойства: Internet Protocol (TCP/IP)»)
задаются:
1. **IP-адрес** — получить автоматически (по DHCP) или фиксированный;
2. **Маска подсети** (при фиксированном адресе);
3. **Адрес основного шлюза** (шлюза по умолчанию);
4. **Адреса DNS-серверов** (основного и запасного) — автоматически или
   фиксированные.

При автоматическом получении адреса все параметры устанавливаются протоколом DHCP.

## 22. Понятие маска подсети

Маска подсети (subnet mask) — 32-битовое число, прилагаемое к IP-адресу в
бесклассовой модели CIDR: на позициях, соответствующих адресу сети, биты
**установлены** (1), на позициях адреса хоста — **сброшены** (0). Адрес сети
вычисляется операцией **конъюнкции (логическое И)** между IP-адресом и маской.
Пример: 255.255.252.0 соответствует 22-битовому адресу сети. Устанавливается
при настройке TCP/IP на компьютере.

## 23. Основные отличия IPv4 от IPv6

- **Длина адреса:** IPv4 — 32 бита (пространство практически исчерпано),
  IPv6 — **128 бит** (увеличение более чем на 20 порядков).
- **Идентификаторы интерфейсов:** концепция IPv6 — каждый узел имеет
  собственный уникальный идентификатор интерфейса; идентификаторы должны
  соответствовать формату IEEE EUI-64: в младших 64 разрядах — MAC-адрес платы
  Ethernet, дополненный с 48 до 64 бит вставкой 16 бит (0xFFFF) между половинами.
- **Автоконфигурация:** IPv6-узел может самостоятельно формировать локально
  действующие адреса; DHCPv6 выделяет глобально уникальные адреса и
  дополнительную конфигурацию.
- **Безопасность:** IPv6 изначально уделяет большое внимание вопросам
  безопасности.
- На первоначальном этапе внедрения — совместное использование обеих версий
  (IPv4-совместимые и IPv4-преобразованные адреса).

## 24. Понятие сетевой порт. Уровень модели TCP/IP

**Порт** — номер, которым идентифицируется процесс, получающий или
отправляющий данные через Транспортный уровень. Понятие порта определено на
**транспортном уровне** TCP/IP. Адресат в сети TCP/IP полностью определяется
тройкой: **IP-адрес + номер порта + тип транспортного протокола (TCP или UDP)**.
Одни и те же номера портов могут использоваться и для UDP, и для TCP.

## 25. Классификация сетевых портов

Три диапазона (по документам IANA):

| Диапазон | Порты | Назначение |
|---|---|---|
| Хорошо известные (well-known) | **0 – 1023** | базовые системные службы (core services) с системными привилегиями |
| Зарегистрированные (registered) | **1024 – 49151** | промышленные приложения и процессы |
| Динамические (dynamic, эфемерные) | **49152 – 65535** | выделяются ОС по мере необходимости прикладным процессам |

Примеры: 20/21 FTP, 22 SSH, 23 Telnet, 25 SMTP, 53 DNS, 67/68 DHCP, 80 WWW
(HTTP), 110 POP3, 143 IMAP4.

## 26. Как посмотреть, какими программами заняты сетевые порты

Утилитой **netstat**: она отражает состояние текущих TCP/IP-соединений хоста и
статистику протоколов; с её помощью можно распечатать номера ожидающих портов
всех соединений, **имена исполняемых файлов, участвующих в подключениях,
идентификаторы соответствующих Windows-процессов** и т.д. Активные соединения:
`netstat -a`; справка: `netstat -?`.

## 27. Понятие архитектуры клиент/сервер

Распределённое приложение имеет архитектуру клиент-сервер, если все его
процессы можно разбить на две группы: **серверы** и **клиенты**; обмен данными
осуществляется только между клиентами и серверами. Главное отличие: **инициатором
обмена данными всегда является клиент** — он обращается за услугой (сервисом) к
серверу. Сервер должен быть активен к моменту запроса, а клиент должен «знать»
параметры сокета сервера; сервер должен уметь распознать клиента. Клиент,
который лишь обеспечивает интерфейс пользователя (основная нагрузка — на
сервере), называют **тонким**. По методу обслуживания серверы делятся на
**итеративные** (обслуживают клиентов поочерёдно) и **параллельные**
(обслуживают нескольких клиентов одновременно, используя средства
распараллеливания ОС). Процесс может быть клиентом одних серверов и
одновременно сервером для других клиентов.

## 28. Сетевая служба. Примеры

**Сетевая служба** — программная реализация протоколов Прикладного уровня
TCP/IP. Работа службы определяется множеством соглашений: спецификации
структур сообщений, регистрация хорошо известного порта, спецификации
программных компонентов. Как правило, служба реализуется в виде сервера,
предоставляющего услуги клиентам; некоторые службы сами выступают клиентами
или обмениваются межсерверными данными (репликация).

**Примеры:** DNS, DHCP, NBT (NetBIOS over TCP/IP), Telnet, FTP, электронная
почта (SMTP, POP3, IMAP4), WWW (HTTP).

## 29. Понятие интерфейса внутренней петли

**Интерфейс внутренней петли (loopback interface)** позволяет двум прикладным
процессам, находящимся **на одном хосте**, обмениваться данными посредством
протокола TCP/IP: дейтаграммы формируются как обычно, но **не покидают пределы
одного хоста** (не затрагивают внешних механизмов за пределами стека TCP/IP).
Для петли зарезервирована сеть 127.0.0.0; ОС назначают адрес **127.0.0.1** и
символическое имя **localhost**. Применяется в основном для отладки
распределённых приложений — моделирование сети на одном компьютере (что и
делается в задании 9: клиент идёт на 127.0.0.1).

## 30. Назначение сетевых служб DNS и DHCP

**DNS (Domain Name System)** — преобразование символических доменных имён в
IP-адреса и обратно (разрешение имён). Распределённая иерархическая база
данных с древовидной структурой (домены .com, .edu, .ru, .by…); обслуживают её
первичные, вторичные и кэширующие DNS-серверы; вершина иерархии — корневые
серверы имён. Даёт наглядную нотацию и не привязывает услуги сервера к
фиксированному адресу. Функции API: gethostbyname / gethostbyaddr.

**DHCP (Dynamic Host Configuration Protocol)** — служба (и протокол)
прикладного уровня, обеспечивающая выделение и доставку хостам IP-адресов и
сопутствующей конфигурации (маска сети, адрес шлюза, адреса DNS-серверов).
Состоит из трёх модулей: DHCP-сервер (порт 67, управляет пулами адресов),
DHCP-клиент (порт 68, часть стека TCP/IP) и ретранслятор (посредник при
недостижимости сервера). Адрес выделяется на срок — аренду; выделение бывает
ручное, автоматическое и динамическое. Позволяет отказаться от фиксированных
IP-адресов.

## 31. Организация, ведающая распределением IP-адресов, доменами верхнего уровня, регистрацией портов

**ICANN** (Internet Corporation for Assigned Names and Numbers) — координирует
систему распределения IP-адресов, управление доменами Internet верхнего уровня
и регистрацию портов/протоколов (включая функции IANA, распределяющей
well-known и registered порты). Также по кодировке ICANN формируются старшие
24 бита MAC-адресов производителей плат.

## 32. Понятие сетевой сокет

**Сокет** — совокупность **IP-адреса и номера порта**; однозначно идентифицирует
прикладной процесс в сети TCP/IP (различают сокеты TCP и сокеты UDP).
Кроме того, сокетом называют **абстрактный объект, представляющий оконечную
точку соединения**. API сокетов — программный интерфейс для обмена данными
между процессами на одном или разных компьютерах; впервые появился в BSD Unix
и описан в стандарте POSIX; в Windows носит название Windows Sockets API.

## 33. Назначение стандарта POSIX

POSIX (Portable Operating System Interface for Unix) — набор документов,
описывающих **интерфейсы между прикладной программой и операционной
системой**. Создан для обеспечения **совместимости различных Unix-подобных
операционных систем и переносимости программ на уровне исходного кода**.
Официально стандарт определён как IEEE 1003, международное название —
ISO/IEC 9945. Интерфейс сокетов описан именно в POSIX, поэтому сокеты
поддерживаются большинством ОС (BSD-сокеты).

## 34. Структура TCP/IP TCP-сервера. Все функции и все параметры

Порядок (по схеме 3.4.2 лекции; реализован в `ServerT_lab2.cpp`):

**WSAStartup → socket → bind → listen → accept → recv/send → closesocket → WSACleanup**

```cpp
// 1. Инициализация библиотеки WS2_32.DLL (до любой функции Winsock)
int WSAStartup(
    WORD     ver,   // [in]  версия Windows Sockets, задаётся макросом MAKEWORD(2,2):
                    //       младший байт - старший номер версии, старший - младший
    LPWSADATA wsd   // [out] указатель на структуру WSADATA (сведения о реализации)
);
// Возврат: 0 - успех, иначе - код ошибки.

// 2. Создание сокета (дескриптора), ориентированного на поток
SOCKET socket(
    int af,    // [in] формат адреса; для TCP/IP - AF_INET
    int type,  // [in] тип сокета: SOCK_STREAM - потоковый (TCP); SOCK_DGRAM - UDP
    int prot   // [in] протокол; для TCP/IP можно указать 0 (NULL)
);
// Возврат: дескриптор сокета, иначе INVALID_SOCKET.

// 3. Заполнение структуры параметров сокета
struct sockaddr_in {
    short          sin_family; // AF_INET
    unsigned short sin_port;   // номер порта (сетевой порядок байт, htons(2000))
    struct in_addr sin_addr;   // IP-адрес: INADDR_ANY - любой адрес хоста;
                               // INADDR_LOOPBACK (0x7f000001) - петля
    char           sin_zero[8];// резерв
};

// 4. Связывание сокета с параметрами (структурой sockaddr_in)
int bind(
    SOCKET                s,  // [in] дескриптор сокета
    const struct sockaddr* a, // [in] указатель на заполненную sockaddr_in
    int                   la  // [in] длина sockaddr_in в байтах (sizeof)
);
// Возврат: 0 - успех, иначе SOCKET_ERROR.

// 5. Переключение сокета в режим прослушивания (только SOCK_STREAM)
int listen(
    SOCKET s,   // [in] дескриптор связанного (bind) сокета
    int    mcq  // [in] максимальная длина очереди подключений; SOMAXCONN - максимум
);
// Возврат: 0 - успех, иначе SOCKET_ERROR.
// После listen клиенты могут выполнять connect; превышение очереди - ошибка connect.

// 6. Ожидание и разрешение подключения: СОЗДАЁТ КАНАЛ
SOCKET accept(
    SOCKET                 s,  // [in]  дескриптор слушающего сокета
    struct sockaddr*       a,  // [out] сюда автоматически записываются параметры
                               //       сокета ПОДКЛЮЧИВШЕГОСЯ клиента
    int*                   la  // [out] указатель на длину sockaddr_in
);
// Возврат: дескриптор НОВОГО сокета (с эфемерным портом) для обмена данными
//          с этим клиентом, иначе INVALID_SOCKET.
// accept ПРИОСТАНАВЛИВАЕТ сервер до вызова connect клиентом.

// 7. Обмен по каналу (через сокет, возвращённый accept!)
int send(
    SOCKET       s,     // [in] дескриптор сокета (канал передачи)
    const char*  buf,   // [in] буфер данных
    int          lbuf,  // [in] количество байт для передачи (можно 0 - конец обмена)
    int          flags  // [in] индикатор режима маршрутизации; NULL (0)
);
// Возврат: число отправленных байт, иначе SOCKET_ERROR.

int recv(
    SOCKET       s,     // [in]  дескриптор сокета (канал приёма)
    char*        buf,   // [out] буфер для приёма
    int          lbuf,  // [in]  размер буфера
    int          flags  // [in]  NULL - буфер очищается после чтения (рекомендуется);
                        //       MSG_PEEK - буфер не очищается
);
// Возврат: число принятых байт; 0 - корректное завершение соединения
//          (или сообщение нулевой длины); SOCKET_ERROR - ошибка.

// 8. Закрытие сокета (клиентского - в цикле, слушающего - при завершении)
int closesocket(SOCKET s);  // [in] дескриптор сокета
// Возврат: 0 - успех, иначе SOCKET_ERROR.

// 9. Завершение работы с библиотекой WS2_32.DLL (освобождение ресурсов)
int WSACleanup(void);
// Возврат: 0 - успех, иначе SOCKET_ERROR.
```

Вспомогательные преобразования: `htons(port)` / `ntohs()` — порт в/из сетевого
порядка байт; `inet_addr("127.0.0.1")` / `inet_ntoa()` — IP из текста в/из
сетевого формата. Ошибка любой функции — код через `WSAGetLastError()`.

В ServerT обмен обёрнут в цикл `while(true)` — итеративный сервер: после
`closesocket(clientSocket)` он возвращается к `accept` и ждёт следующего клиента.

## 35. Структура TCP/IP TCP-клиента. Все функции и все параметры

Порядок (реализован в `ClientT_lab2.cpp`):

**WSAStartup → socket → connect → send/recv → closesocket → WSACleanup**

```cpp
// 1-2. WSAStartup(MAKEWORD(2,2), &wsaData) и socket(AF_INET, SOCK_STREAM, 0)
//      - точно такие же, как у сервера (см. вопрос 34).

// 3. Установка соединения с сокетом сервера. Канал создаётся
//    взаимодействием accept (сервер) и connect (клиент).
int connect(
    SOCKET                s,  // [in] дескриптор потокового сокета клиента
    const struct sockaddr* a, // [in] указатель на sockaddr_in, ИНИЦИАЛИЗИРОВАННУЮ
                              //     параметрами сокета СЕРВЕРА (семейство, IP, порт)
    int                   la  // [in] длина sockaddr_in в байтах
);
// Возврат: 0 - успех, иначе SOCKET_ERROR (например WSAECONNREFUSED -
//          на порту никто не слушает).
// Для connect достаточно предварительно создать сокет; bind НЕ нужен -
// Windows сама выделяет клиенту эфемерный порт.

// 4. Обмен данными: send(...) и recv(...) - те же функции и параметры,
//    что у сервера (вопрос 34), но с дескриптором сокета КЛИЕНТА.

// 5-6. closesocket(cS); WSACleanup();
```

Ключевые отличия клиента от сервера:
- **нет bind и listen** — клиенту не нужны фиксированные параметры: Windows
  выделяет ему эфемерный порт, и клиент сообщает свои параметры серверу
  автоматически при connect/передаче;
- **нет accept** — вместо него `connect` к заранее известным IP-адресу и порту
  сервера;
- инициатор обмена — всегда клиент.

```
g++ -std=c++17 -o ServerT.exe ServerT/ServerT_lab2.cpp -lws2_32
g++ -std=c++17 -o ClientT.exe ClientT/ClientT_lab2.cpp -lws2_32

ServerT.exe [порт]                     # по умолчанию 2000
```

Во время обмена `netstat -a` показывает пару ESTABLISHED-строк на соединение

до подключения у сервера строка `0.0.0.0:2000 ... LISTENING`.
