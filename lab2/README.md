# Лабораторная работа № 2. Обмен данными по TCP-соединению

Клиент-серверное приложение на Winsock2 (TCP, порт 2000) в стиле пособия:
`GetErrorMsgText` / `SetErrorMsgText` / `try-catch` / `throw`.

- `ServerT/ServerT_lab2.cpp` — серверная часть (задания 1–6, 10, 11, 14, 15)
- `ClientT/ClientT_lab2.cpp` — клиентская часть (задания 7–9, 11–14)

> Копии этих же файлов с полным `GetErrorMsgText` (русские тексты ошибок)
> лежат в `PSP/ServerT_lab2/` и `PSP/ClientT_lab2/` (Visual Studio-проекты).

## Как создать в Visual Studio

1. Создать решение с двумя консольными проектами: `ServerT` и `ClientT`
   (Win32 Console Application, пустой проект → добавить `.cpp`).
2. В оба файла уже включены `#pragma comment(lib, "WS2_32.lib")` — отдельно
   подключать библиотеку в настройках компоновщика не нужно.
3. Компилировать в режиме Debug (по требованию практикума).

## Порядок запуска (задание 9)

1. Запустить `ServerT` — он остановится («зависет») на `accept` (задание 6).
2. Запустить `ClientT` на том же компьютере — сервер выйдет из ожидания.
3. `ClientT` спросит число сообщений (задание 14), отправит их серверу,
   получит эхо-ответы, выведет время обмена и завершится.
4. `ServerT` после нулевого сообщения закроет сокет клиента и снова уйдёт
   в `accept` — готов принять нового клиента (задание 15).
   Останов сервера — закрыть окно консоли.

## Задание 14: анализ netstat

Во время обмена выполнить на клиенте и на сервере:

```
netstat -a
```

Найти строку вида (адрес/порт могут отличаться):

```
TCP    127.0.0.1:51870    127.0.0.1:2000    ESTABLISHED
```

- порт **2000** — сокет сервера (после `bind`);
- второй порт (динамический, 49152–65535) — клиентский сокет;
- состояние `ESTABLISHED` — установленное TCP-соединение ClientT–ServerT;
- при ожидании клиента у сервера строка `0.0.0.0:2000 … LISTENING`.

## Примечания

- Задания 1–6 выполняются пошагово: финальный `ServerT.cpp` уже содержит
  всё сразу, но для отчёта задания 3–6 можно показывать промежуточные
  версии (просто комментируя нижние блоки).
- `send(cS, "", 0, 0)` отправляет сообщение нулевой длины; закрытие сокета
  клиентом также приводит к возврату 0 из `recv` на сервере.
